# P4 — เงินและการแจ้งเตือน · acceptance matrix

Worker F · branch `feat/p4-money`. Browser rows run on both Playwright projects (desktop and phone 412 px).
Spec files: `tests/e2e/p4-deposit.spec.ts` (customer deposit by PromptPay + slip, storage and RPC refusals),
`tests/e2e/p4-review.spec.ts` (staff review queue `/admin/payments`), `tests/e2e/p4-integrations.spec.ts`
(`/admin/integrations`, secrets, push keys), `tests/e2e/p4-routes.spec.ts` (route guards, 503 without the service role);
unit rows in `tests/unit/p4-*.test.ts`.
Data is created through the staff account under RLS (customer name `E2E P4 <run id>`, helper `p4-helpers.ts`), links
through `rpc('issue_job_link')`; cleanup cancels the bookings and revokes the links (no deletes). Integration rows the
specs change (`promptpay`, `line`, `slip`) are snapshotted first and restored in `afterAll`.

"needs key" = the row needs `SUPABASE_SECRET_KEY` (service role: Vault reads, provider calls, webhooks) or a real provider
account; without it the row is **NOT RUN** and the 503 behaviour is covered by the P4-4x rows instead.
